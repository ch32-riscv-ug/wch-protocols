# 適当に挿してから対応を探す — P4 と CH32 のピン当て

状態: **設計メモ**(2026-09-13。ピンの可否は [E087](../experiments/e087_p4_pin_survey/README.ja.md) で実測。**探索そのものは未実装**)

**1 対 1 で配線するのが辛い**ので、**電源と GND だけ合わせて残りは適当に挿し、software で対応を見つける**。そのための材料と手順。

## 1. どこに挿すか(WT9932P4-TINY、実測済み)

| | ピン | 根拠 |
|---|---|---|
| **第一候補** | **J7 の IO16〜IO23**(8 本連続) | 素の 3.3 V GPIO。**8 本とも ADC1 ch0〜7**。pull 追従・駆動とも確認済み |
| **第二候補** | **J7 の IO26〜IO33**(8 本連続) | 素の 3.3 V GPIO。同上 |
| 追加 | J6 の IO9〜IO15、IO49 / IO50 / IO52 / IO53 / IO54 | 素の 3.3 V GPIO。pull 追従を確認 |
| 注意 | IO2〜IO5 | JTAG(MTCK / MTDI / MTMS)兼用 |
| **禁止** | **IO24 / IO25** | **J3(書き込み用 USB)。触ると console が落ちて挿し直しになる**([E087](../experiments/e087_p4_pin_survey/README.ja.md) で実際に踏んだ) |
| 禁止 | IO0 / IO1 / IO7 / IO8 | CSI(カメラ)コネクタ |
| 禁止 | IO39〜IO48 | SD カード。**電源が LDO_VO4 で 1.8 V 設定がありうる**。3.3 V を入れない |
| 禁止 | IO34 / IO36 / IO37 / IO38 | strapping(起動時の値が boot mode を決める)。IO37 / IO38 は UART0 |
| 禁止 | IO51 | 基板が握っている |

**16 本(IO16〜23 + IO26〜33)を既定の作業領域にするのがよい。** 連続していて、ヘッダ上で隣接し、**片方は ADC も使える**。

> **チップ側の予約はゼロ。** P4 は flash / PSRAM / USB をすべて専用パッドに置くので、**使えないピンは基板の都合だけ**である。

## 2. P4 側がアナログを作る

**CH32V 系は DAC を積むものが少ない**(V30x の一部のみ)。したがって **3 値を作るのは P4、読むのは CH32 の ADC**。

P4 は `pull-up` と `pull-down` を**同時に**掛けられる(`GPIO_PULLUP_PULLDOWN`)。実測([E087](../experiments/e087_p4_pin_survey/README.ja.md)):

| 設定 | 電圧 |
|---|---:|
| pull-down のみ | **1 mV** |
| **両方** | **1460〜1487 mV** |
| pull-up のみ | **3278 mV** |
| floating | 1354〜2424 mV(**不定**) |

**3.3/2 = 1.65 V ではなく約 1.47 V** だが、**3 値は十分離れている**(ピン間のばらつきは 27 mV)。

**注意 2 つ。**

- **floating の読みは意味を持たない。** 「未接続」を floating で判定してはいけない
- **CH32 を繋ぐと分圧が動く。** 中間電圧は弱い pull(数十 kΩ)の分圧なので、**CH32 側は高インピーダンスで読む**こと。CH32 側で pull を有効にすると中間が潰れる

## 3. 探索の手順

### 段階 0 — 電源と GND だけ人が合わせる

ここだけは間違えられない。

### 段階 1 — RVSWD の 2 本を見つける

**人が選んで結線してもよい**が、**総当たりで探せる**。候補 N 本から順序付き 2 本を選ぶので **N×(N−1) 通り**(16 本なら 240 通り)。**RVSWD は成功すると chip ID を返す**ので、**当たれば 2 本とその向きが同時に確定する**。1 回が数 ms なら全体で数秒。

> 既存の RVSWD の波形知識は [protocols/link-to-target](../protocols/link-to-target.ja.md) と [E007](../experiments/e007_wire_rvswd_frame/README.ja.md) にある。

### 段階 2 — CH32 に探索 firmware を焼く

段階 1 が済めば RVSWD で焼ける。**ここから先は両側に software がある**ので楽になる。

### 段階 3 — 残りを符号で一気に当てる

**1 本ずつ順に振るのは遅い**(N 回)。**各ピンに固有の符号を割り当てて同時に振る**と **`ceil(log2(N+1))` 回**で済む(16 本なら **5 回**)。

- **P4**: 全ピンを同時に駆動する。slot `k` では「自分の番号の bit `k`」を出す
- **CH32**: 全ピンを **digital input + pull-down** で読む。**未接続は常に 0** になるので、符号が全 0 のピンは「繋がっていない」
- 5 slot 読み終えると、**CH32 の各ピンが「P4 の何番に繋がっているか」を直接得る**

**逆向き**(CH32 が駆動、P4 が読む)も同じ手順でできる。**両方やると、片側の読み違い・断線・短絡が突き合わせで出る**。

### 段階 4 — アナログで裏を取る

符号は「1 / 0 が読めた」だけなので、**電源に短絡していても 1 に見える**。そこで **P4 が 1 本だけ中間電圧(両 pull)にし、CH32 の ADC で読む**。

- **約 1.47 V が読めれば、その線は「P4 の、駆動していないピン」に繋がっている**と確定する
- 3.3 V や 0 V に張り付いていれば、**電源 / GND か、他の何かが駆動している**
- **CH32 側は高インピーダンスで読むこと**(pull を切る)

**これは短絡の検出にも効く。** 2 本が互いに短絡していれば、片方を中間にしたときもう片方も中間になる。
