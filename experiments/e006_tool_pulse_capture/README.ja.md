# E006 道具: パルス幅の生成と記録(1 線・RMT)

状態: **完了**(2026-09-04)    <!-- 計画 → 実行中 → 完了 / 中断 -->

規則: [../README.ja.md](../README.ja.md) / 台帳: [../LEDGER.ja.md](../LEDGER.ja.md) / 前段: [E005](../e005_tool_clocked_capture/README.ja.md)(2 線・クロック同期の道具)

## 問い

**ESP32-S3 の RMT で、SWIO 相当のパルス幅(短 ≈ 290 ns / 長 ≈ 890 ns)を生成し、もう 1 台が幅を測れるか。分解能と測れる最小幅はいくつか。**

E005 と対になる道具。E005 は**クロックのある 2 線**用、こちらは**クロックのない 1 線**(パルス幅符号化)用。

## 仮説

**測れる。** ESP32-S3 の RMT は APB 80 MHz を分周した tick で幅を持つので、**80 MHz なら 12.5 ns/tick**。SWIO の短パルス 290 ns は **23 tick** に相当し、十分な分解能がある。

比較対象として、安価な LA(fx2lafw、24 MS/s)では 290 ns が **約 7 サンプル**にしかならない。**RMT の方が細かい**可能性がある。

数値の根拠: `rv003usb/rvswdio_programmer/bitbang_rvswdio_ch32v003.h` の実測コメント(48 MHz の CH32V003 が TIM1+DMA で線を出している実装)— `Send1Bit` が 288〜296 ns、`Send0Bit` が 888〜904 ns、bit 周期 1.16〜1.33 us。

## 反証条件

1. `rmtInit` が高い tick 周波数を受け付けない(80 MHz が通らない)
2. 生成はできるが**受信側が短いパルスを取りこぼす**(RMT の RX フィルタ、または最小幅の制約)
3. 測れるが**値が不正確**(公称との差が大きい、ばらつく)
4. 受信の symbol 数が足りず、連続したパルス列を取り切れない

## 方法

1. 両 board に同じ sketch。role は host からのコマンドで決める。GPIO19 を 1 線として使う(E003 で直結を確認済み)。
2. コマンド:
   - `I<tick_hz>,<dir>` — RMT を初期化(dir 0=RX / 1=TX)。成否と実際の tick を返す
   - `P<lo>,<hi>,<count>` — LOW を `lo` tick、HIGH を `hi` tick のパルスを `count` 個送る(SWIO は idle HIGH、LOW に引いて 0/1 を表す)
   - `C<count>` — `count` symbol 分の取り込みを用意して `ARMED` を返し、取れた幅を tick で返す
   - `?` 識別
3. **tick 周波数を掃引**: 80 / 40 / 20 / 10 MHz。`rmtInit` が通る最大を確認する(反証条件 1)。
4. **パルス幅を掃引**: 公称 250 / 290 / 500 / 890 / 2000 ns。各 8 パルス × 3 回。
5. 受信値(tick)を ns に直し、**公称との差**と**ばらつき(min/max)**を記録する。

## 対象外

| 落とすもの | 行き先 |
|---|---|
| SWIO の 0/1 閾値そのもの(実 CH32 が何で判定するか) | 候補 `swio-threshold`。**実 target が要る**。ここは道具の性能だけ |
| SWIO のフレーム構造(start + addr7 + data32) | 候補 `wire-bitstream` |
| 実 CH32 target との通信 | 対象外 |
| open-drain / pull-up の電気的挙動 | 対象外(両 board とも 3.3 V、push-pull で送る) |

## 必要な環境

**peer 対 2 枚**(常設 v2)。GPIO19 の 1 線のみ使用。配線変更なし。

## ベンチ種別

**常設 v2**。

## 記録する数値

| 項目 | 単位 | 備考 |
|---|---|---|
| `rmtInit` が通る最大 tick 周波数 | MHz | **道具の分解能** |
| 公称幅ごとの受信値 | ns | min / median / max、8 パルス × 3 回 |
| 公称との差 | ns | 系統誤差があるか |

## 完了条件

- 公称 290 ns と 890 ns を区別して測れれば **完了**(SWIO の道具として使える)
- 測れなければ原因を記録し、代替(LA / 別の周辺機能)を未決に回して完了

## 影響

- 通れば → **`swio-threshold` の機材要件が変わる可能性がある**。ただし閾値そのものは実 CH32 が何で判定するかなので、**この道具だけでは決まらない**(送信側の幅を正確に作れることの保証にはなる)
- 使い捨てベンチ(LA)の必要性を判断する材料になる
- 仕様の status は動かない(道具の確認)

## 結果

run: `_runs/E006_*_s3_peer/`。**`rmtInit` は 80 MHz を受け付けた → 12.5 ns/tick。**

| 公称 | tick | 実測 min | med | max | symbol |
|---:|---:|---:|---:|---:|:---:|
| 250 ns | 20 | 250.0 | 250.0 | 250.0 | 8/8 |
| **290 ns** | 23 | **287.5** | 287.5 | 287.5 | 8/8 |
| 500 ns | 40 | 500.0 | 500.0 | 500.0 | 8/8 |
| **890 ns** | 71 | **887.5** | 887.5 | 887.5 | 8/8 |
| 2000 ns | 160 | 2000.0 | 2000.0 | 2000.0 | 8/8 |

| 反証条件 | 結果 |
|---|---|
| 1. 高い tick 周波数を受け付けない | 起きず(**80 MHz が通った**) |
| 2. 短いパルスを取りこぼす | 起きず(250 ns でも 8/8) |
| 3. 値が不正確・ばらつく | 起きず(**24 サンプルすべてで min=med=max**) |
| 4. symbol 数が足りない | 起きず |

## 事実

1. **分解能 12.5 ns。** `rmtInit` は 80 MHz を受け付ける。SWIO の短パルス 290 ns は 23 tick に相当。
2. **実測値は量子化された公称値と完全に一致し、ばらつきが観測されない**(min = med = max、公称 290 → 287.5 = 23 tick、890 → 887.5 = 71 tick)。差は tick 量子化そのもので、誤差ではない。
3. **250 ns でも 8/8 取れる**。RX のフィルタ(`rmtSetRxMinThreshold(0)`)を切れば短パルスは落ちない。
4. **290 ns と 890 ns は明確に分離できる**(287.5 < 887.5)。SWIO の 0/1 を幅で見分ける道具として成立する。
5. **安価な LA(24 MS/s)より細かい。** 290 ns は LA では約 7 サンプルだが、RMT では 23 tick。

## 候補

- **SWIO の送信側は RMT TX で作る**(採用候補)。幅を tick 単位で正確に指定でき、ばらつきが無い。将来 CH32RVProbe の ESP32 phy にそのまま使える([generic-probe-design §4](../../references/generic-probe-design.ja.md) の「ペリフェラル支援」段)。
- 受信側は RMT RX で幅を測る道具として確定。

## 未決 / 限界(誤読しないための注記)

- **この実験が示したのは「道具の精度」であって「CH32 が何を受け付けるか」ではない。** 送受とも ESP32-S3 の RMT で、直結の短い線。**SWIO の 0/1 閾値は実 CH32 でしか決まらない**(候補 `swio-threshold` は実 target が必須のまま)。
- 2 台の 80 MHz は別々の水晶だが、290 ns 程度では 1 tick 未満のずれしか出ないので、一致は当然。**長時間の絶対精度は未測定**。
- 電気的な立ち上がり時間(前段資料では ~120 ns)は RMT では見えない。**波形の形が要るなら LA が要る**。

## 反映

- 台帳 [E006](../LEDGER.ja.md) に道具として登録。**仕様値: 12.5 ns/tick、250 ns 以上のパルスを取りこぼしなく測定、ばらつき観測されず**。
- 候補 `swio-threshold` の機材欄を更新 — **幅の生成と測定は常設 v2 で足りる。実 target と、波形の形が要る場合の LA が残る**。
- 仕様の status は動かない(道具の確認)。
