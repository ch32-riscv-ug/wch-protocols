# E169 止まった X035 を reset させる WCH-LinkE のコマンドはどれか

状態: **完了(2026-09-25)**

## 問い

E168 で、E164 の止まった X035 は、電源が落ちないまま reset(havereset)される、と分かった。E165 の 2c で過去の収録を洗い直すと、線上に reset の操作(ndmreset・PFIC)は無く、reset の時刻は特殊消去の 136〜142 ms に絞れた。

- どの LinkE のコマンドが引き金か。
- target が自分で(時間が経つと)reset するのか。

## 手順

- 機材: WCH-LinkE fw 2.22 `FC928F068181` → CH32X035C8T6。外部との接続は 3V3・SWDIO・SWCLK・TX・RX・GND で、RST は未接続。3V3 は LinkE から。
- [`trigger.py`](trigger.py) で、1 回の試行ごとに次を行う。
  1. 止める: E164 の HPRE `1001` の clockwatch を焼き、`target info` で止める(UID が `-` などに化けることを確かめる)。
  2. 処置(1 つの USB session): 次のどれか 1 つ。
     - 何もせず 3 s 待つ
     - AttachChip を 5 回
     - RedetectChip + DetachChip を 5 回
     - 特殊消去 `81 0d 02 0f 0d` を 1 回
     - 止めてから 0 / 5 / 15 s 待って特殊消去を 1 回
  3. 判定(新しい session): AttachChip → DMSTATUS → abstract memory read で RCC_CFGR0 / FLASH_ACTLR を読む。
  4. 戻す: 特殊消去を、応答が `82 0d 01 0f` になるまで(1 回ごとに別の session で)送り、`target info` で UID が読めることを確かめる。
- 生の値と USB の往復は `out/*.json`。

## 結果

| 処置 | 処置の応答 | 判定の AttachChip | 判定の DMSTATUS | 戻すのに要った特殊消去 |
|---|---|---|---|---|
| 何もせず 3 s | ― | `81 55 01 01`(失敗) | 読めない(DmiOp は `ffffffff`) | `00` → `0f` |
| AttachChip ×5 | 5 回とも `81 55 01 01` | 失敗 | 読めない | `00` → `0f` |
| RedetectChip + DetachChip ×5 | すべて受理 | 失敗 | 読めない | `00` → `0f` |
| **特殊消去 ×1** | **`82 0d 01 00`** | **成功** | **`0x000c0382`(havereset)**、CFGR0 `0`、ACTLR `2` | **`0f`(1 回目で成功)** |
| 0 s 待って特殊消去 | `00` | 成功 | `0x000c0382` | `0f` |
| 5 s 待って特殊消去 | `00` | 成功 | `0x000c0382` | `0f` |
| 15 s 待って特殊消去 | `00` | 成功 | `0x000c0382` | `0f` |

- **止まった X035 を reset させるのは、特殊消去のコマンドである。** 応答が `00`(消去していない)でも、reset はかかる。
- AttachChip・RedetectChip・DetachChip・待つだけでは、何も変わらない。target が時間で自分から reset する、という見方は否定される(3 s・15 s では戻らず、E164 では数分でも戻らなかった)。
- 止めてから特殊消去までの待ち時間(0 / 5 / 15 s)は結果に影響しない。どれも「1 回目 `00` → 2 回目 `0f`」だった。
- 判定で読んだ CFGR0 `0` / ACTLR `2` は、判定の AttachChip の中で LinkE 自身が書く値と同じなので、reset の既定値かどうかはこの判定からは分からない(E165 の `31` では、消去の後に既定値の `0x50` / `0` を読んでいる)。

## 結論

- 止まった X035 に対する特殊消去は、1 回目で target を reset する(電源は落ちない。E168)が、halt が取れず消去はしない(`00`)。reset で app が起動し直して普通に動く状態に戻るので、2 回目の特殊消去では halt が取れて消去する(`0f`)。これが「1 回目 `00` → 次で `0f`」の正体である。E165 の `31` だけは 1 回目で `0f` だった(理由は未確認)。
- reset を掛けるのは、特殊消去の中の LinkE の動作である。RST は未接続、3V3 は切れていない(E167・E168)、DMI に ndmreset / PFIC の書込みは無い(E165 の 2c)。残るのは、特殊消去の中の SWD の動き(止まった target に対する線の初期化の繰り返しなど)である。その中のどれが効くのかは、線の初期化だけを送れる probe で再現しないと決められない。
