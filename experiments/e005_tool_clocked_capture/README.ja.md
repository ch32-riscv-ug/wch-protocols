# E005 道具: クロック同期のビット取り込み(2 線)

状態: **完了**(2026-09-04)    <!-- 計画 → 実行中 → 完了 / 中断 -->

規則: [../README.ja.md](../README.ja.md) / 台帳: [../LEDGER.ja.md](../LEDGER.ja.md) / 前段: [E003](../e003_smoke_peer/README.ja.md)(2 線の直結を確認)

## 問い

**peer 対の 2 線で、片方が出したクロック同期の bit 列を、もう片方が正しく取り込めるか。取り込める最短のクロック周期はいくつか。**

これは実験ではなく**道具の性能測定**。以後の線層の実験([`wire-bitstream`](../LEDGER.ja.md) など)がこの道具の上に乗るので、先に限界を知っておく。

## 仮説

**取り込める。** [E003](../e003_smoke_peer/README.ja.md) で GPIO19↔19 / 20↔20 の双方向直結が確認済み。19 を SWCLK、20 を SWDIO に見立てれば **RVSWD と同じ 2 線構成**になる([link-to-target §3](../../protocols/link-to-target.ja.md):clock が HIGH の間に sample、data は clock が LOW の間に変化、MSB first)。

クロック周期の下限は **受信側の `digitalRead` + ループのコスト**で決まると予想する。ESP32-S3 の Arduino `digitalWrite`/`digitalRead` は数百 ns 級なので、**半周期 1 µs 前後が下限**になると見る。

## 反証条件

1. どの周期でも bit 列が一致しない(配線・サンプル位相の問題)
2. 一致するが**取りこぼしが間欠的**(3 回中 1 回でも不一致なら該当)
3. 一致する周期が遅すぎて道具として使えない(半周期 20 µs でも駄目、など)

## 方法

1. 両 board に同じ sketch を焼く(役割は host からのコマンドで決める)。
2. コマンド:
   - `A<bits>` — 受信側: `bits` 個の bit を取り込む用意をして `ARMED` を返し、SWCLK の立ち上がりで SWDIO をサンプルする。完了で `BITS=<hex>`、時間切れで `TIMEOUT=<取れた数>`
   - `T<half_us>,<bits>` — 送信側: 既知パターンを `bits` 個、半周期 `half_us` µs で送る。**data は clock LOW の間に変化させ、clock HIGH の間に安定させる**
   - `?` 識別 / `Z` 解放
3. 既知パターンは `A5 5A C3 3C` の繰り返し(host 側でも同じものを計算して比較)。
4. **半周期を掃引**: 20 / 10 / 5 / 2 / 1 / 0(遅延なし)µs。各 3 回。
5. 一致した最短周期と、そのときの実測ビットレートを記録する。

## 必要な環境

**peer 対 2 枚**(常設 v2)。配線は変更しない(GPIO19 = SWCLK 相当、GPIO20 = SWDIO 相当として使う)。

> 19/20 は ESP32-S3 の native USB ピン。**GPIO として使う間は native USB を使えない**が、この実験は CH340 経由の UART を使うので支障はない。

## ベンチ種別

**常設 v2**。

## 記録する数値

| 項目 | 単位 | 備考 |
|---|---|---|
| 半周期ごとの一致 / 不一致 | 3 回中 n 回 | 掃引の全点 |

## 完了条件

- 一致する周期が 1 つでもあれば **完了**(道具として使える。限界値が仕様になる)
- どの周期でも一致しなければ、原因を記録して完了(道具は別の作り方にする)

## 影響

- 通れば → **LA なしで RVSWD の bit 列を検証できる道具**が手に入る。候補 `wire-bitstream` の一部が常設 v2 で消化でき、使い捨てベンチ(LA)の負担が減る
- 仕様の status は動かない(道具の確認なので)

## 事実

1. **peer 対の 2 線で、クロック同期の bit 列を取り込める。** GPIO19 を SWCLK、GPIO20 を SWDIO に見立てた [link-to-target §3](../../protocols/link-to-target.ja.md) の規則(data は clock LOW で変化、clock HIGH でサンプル、MSB first)がそのまま動く。
2. **道具の仕様値は「半周期 5 us 以上 = 100 kbps まで」**。3/3 で一致するのはここまで。
3. **2 us 以下は間欠的に落ちる**(2/3 → 1/3)。**遅延なしでは 2 bit しか拾えず、受信側のポーリングループが完全に追いつかない。** 送信側が受信側より速いことが律速。
4. **失敗の仕方が「取りこぼし」であって「位相ずれ」ではない**(TIMEOUT で bit 数が足りない形。拾えた分の値は正しい)。→ サンプル位相の設計は正しく、純粋に速度の問題。

## 候補

- **当面の使い方: 検証時は送信側を 100 kbps 以下に落とす。** 符号(bit 列)の検証には十分で、[link-to-target §3](../../protocols/link-to-target.ja.md) のフレーム構造は速度に依存しない。
- **速くしたい場合の手**(いずれも未検証): (a) `digitalRead` をレジスタ直読みに置換、(b) GPIO 割り込み、(c) **ESP32-S3 の SPI slave 周辺機能で受ける**(RVSWD は本質的にクロック付きシリアルなので、hardware で MHz 級に届く可能性)、(d) DEDIC_GPIO。**(c) が本命**。

## 未決

- 実 RVSWD の動作速度で観測したいときにどうするか → 候補 `tool-fast-capture`(SPI slave 案)。**いまの道具は「符号の検証」専用で、実速度の観測には使えない**。
- 送信側の上限(この実験では受信側が先に律速したので、送信側がどこまで速く出せるかは未測定)。

## 反映
