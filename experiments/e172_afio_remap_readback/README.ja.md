# E172 USART / SPI / I2C の割り当てはどこで固定すると安いか。route が使えないことは読み返しで分かるか

状態: **完了（2026-10-14）**

ArduinoCore-CH32RV で、複数インスタンスのあるペリフェラル（USART / SPI / I2C）を、インスタンスごとのボードメニュー
（AUTO = begin 時割り当て / Disable / FIX = ピン固定）で扱う案を検討するための実測。

## 問い

1. インスタンスの割り当てをビルド時に固定する場合と `begin()` 時に決める場合で、Flash / RAM はどれだけ違うか。
   使わないインスタンスを Disable にすると、どれだけ減るか。
2. 全 USART のベクタを1つのハンドラの別名にし、IRQ 番号を `mcause` から取る方式は、各世代のコアで動くか。
3. 表にある route がそのチップで使えないこと（ダイに route が無い、パッドが無い）を、remap / GPIO の読み返しで
   検出できるか。その費用はどれだけか。

## 手順

- サイズ：スケッチ内の試作ドライバー（`size_proto/`）で、USART ごとのモード（0 未使用 / 1 begin 時割り当て /
  2 ビルド時固定）をビルド定義で切り替え、空のスケッチとの差を測る（`measure.sh`、ArduinoCore-CH32RV の作業ツリー）。
- 共有ハンドラ：試作を X035（OEP + fixture UART、USART4）、V003（OEP + fixture UART、USART1）、
  V103（CH549 WCH-Link の CDC、USART1〜3 を有効）に焼き、エコーと定期出力を確認。
- 読み返し：デバッガ経由（ch32rv `write` / `read`）で AFIO の remap フィールドと GPIO の設定レジスタを書いて読み返す。
  `regprobe.py`（レジスタ単位）、`routescan.py`（系列の全品番の route の和集合を1チップで走査）、
  `nibble.py`（GPIO 設定の 16 値）、`v006_remap.py`（V006 の remap レジスタの位置の機能確認）。
  デバッグ線のピン（PD1、PA13 / PA14、PC18 / PC19）は走査から除外。各操作のあと元の値に戻す。

## 結果

### A. サイズ（空のスケッチとの差、Flash / RAM バイト。試作はパリティ・ストップビット設定と setRoute API を含まない）

| 構成 | V003（USART 1） | X035（4） | V307（5） |
|---|---|---|---|
| 現行コア（`SerialN`） | 1528 / 200 | 2380 / 788 | 2664 / 984 |
| begin 時割り当て：全 USART 有効 | — | 1552 / 180 | 1612 / 184 |
| begin 時割り当て：USART2 + USART4 | — | 1424 / 172 | — |
| begin 時割り当て：使う1本のみ | 1144 / 168 | 1188 / 168 | 1220 / 168 |
| ビルド時固定（1本） | 908 / 164 | 768 / 164 | 784 / 164 |

- 現行コアは、使わない USART のハンドラ（各約 190 B）、オブジェクト（各 196 B の RAM）、起動時の初期化コード
  （X035 で 402 B）を全部リンクしている。I2C も同様（V307 で EV / ER の 4 ハンドラ × 約 172 B）。
- begin 時割り当てで有効な USART を1本増やすごとに、X035 で約 120 B、V307 で約 100 B（RAM +4 B）。
  内訳は設定表と route 表の行（約 56 B）、共有ハンドラの IRQ 探索、`begin()` の比較処理。ハンドラのコードは増えない
  （ベクタは共有関数の別名）。
- ビルド時固定は、同じ1本の begin 時割り当てより V003 で約 240 B、X035 で約 420 B、V307 で約 440 B 軽い
  （`begin()` の定数畳み込み、ピン探索と route 表が不要、専用ハンドラへの本体の展開）。
- `constexpr` コンストラクタだけにすると、バッファごとオブジェクトが `.data` に移り、Flash に同じ大きさの初期値が要る。
  設定は `const` 表、オブジェクトはゼロ初期化の状態だけ、が正しい形。

### B. 共有ハンドラ（ベクタの別名 + `mcause`）

| チップ | コア / ベクタ形式 | 結果 |
|---|---|---|
| X035 | V4 / アドレス表 | エコー・定期出力とも正常（USART2 も別名で登録） |
| V003 | V2（ハードウェアのレジスタ退避） / アドレス表 | 正常 |
| V103 | V3A / ジャンプ命令の表 | 正常（USART1〜3 を有効） |

ネストした割り込み（優先度の異なる割り込みの同時発生）は未確認。

### C. remap フィールドの読み返し

| チップ | 書き込みが残るビット | 所見 |
|---|---|---|
| X035 F8U6 / C8T6 | PCFR1 = 0x00FFFFFF（同じ） | 予約値（USART4 = 6・7）も残る |
| V003 F4P6 / F4U6 | PCFR1 = 0x00E683C7（同じ） | |
| V006 K8U6 | 0x04 = 0x00E683C7、0x0C = 0x007FFFFF | D を参照 |
| V203 C8T6（D6） | PCFR1 = 0x0002FFC7、PCFR2 = 0x00010000 | USART2（bit3）と USART3（bit4・5）の remap ビットが無い。PCFR2 bit26 も無い |
| V103 R8T6 | PCFR1 = 0x0000FFFF、PCFR2 = なし | USART3 フィールドは予約値（2）も残る |

ダイに無い route は読み返しで検出できる。実装されたフィールドの予約値は検出できない（route 表には載らないので問題ない）。

### D. V006 の remap レジスタは 0x0C

USART1 を送信可能にし（TX は待機中 High）、route 3 の TX（PC0）を AF 出力にして入力レベルを読んだ。

| 書き先 | PC0 | 読み返し |
|---|---|---|
| どちらも 0 | 0 | — |
| 0x04 に route 3 | 0（remap されない） | 0x04 = 0（残らない） |
| 0x0C に route 3 | 1（TX が出る） | 0x0C = 0xC0 |

CH32V00XRM の AFIO レジスタ一覧（EXTICR = 0x40010008、PCFR1 = 0x4001000C）と一致。ArduinoCore-CH32RV は全系列で
0x04 に書いていたため、V006 系（V002 / V004 / V005 / V006 / V007 / M007）で既定以外の route が効いていなかった。
同日 ArduinoCore-CH32RV d1a3577 で修正し、`Serial2.begin(115200, SERIAL_8N1, PA5, PA4)` で PA4 に TX が出ることを確認。

### E. 系列の全品番の route の和集合を1チップで走査（`routescan.py`、`scan-*.json`）

| チップ | 結果 |
|---|---|
| V003 F4P6、V006 K8U6、V103 R8T6、V307 VCT6 | 全 route で remap・ピンとも ok |
| L103 C8T6 | 全 ok（USART3 の値 2 / 3 は OSC_IN / OSC_OUT で、ピンは未試験） |
| V203 C8T6 | USART3 値 1（PC10 / PC11）：remap NG・ピン NG。**USART4 値 0：remap ok、PB0 / PB1 ok、PC10 / PC11 NG** |
| X035 C8T6 | 下の F を参照 |

**同じ (USART, remap 値) が、ダイによって別のピンを選ぶ。** V203 の USART4 値 0 は、D6 ダイでは PB0 / PB1、D8 ダイでは
PC10 / PC11。和集合の route 表に「USART4・値 0 = PC10 / PC11」の行があると、D6 では remap の読み返しは通り、
USART は黙って PB0 / PB1 に出る。この例では D6 ダイに PC10 / PC11 のパッドが無いので、GPIO の読み返しで検出できる。

ダイにパッドが無いピンは、GPIO 設定が常に 0 で読める（V003 の PA0、V006 K8U6 の PB7、V203 C8T6 の PC0）。
ダイにはあるがパッケージに出ていないピン（X035 F8U6 の PA10）は、書いた通りに読め、プルにも従う（検出できない）。

### F. X035 C8T6 の CNF が `01` に固定されたピン

X035 C8T6 の PA9、PB9、PB17、PC17 は、GPIO 設定の CNF（上位2ビット）が `01` に固定され、MODE（下位2ビット）だけ書ける。
16 値を書いた結果は `0→4, 1→5, 2→6, 3→7, 8→4, b→7 …`。

- 入力：浮き入力にはなるが、プルアップ / プルダウンは効かない。
- 出力：AF 出力にできない。これらを TX / MOSI / SCL / SDA に使う route（USART4 値 3・5、SPI1 値 1、I2C1 値 2・4）は
  この品番では使えない。

PC17 はデータシート V2.3 のピン表の注 4（F8U6 / D8U6 以外は PC10 と PC17 が内部で短絡、出力禁止）で説明できる。
PA9 / PB9 / PB17 はデータシートに記述が無い（未解決）。

### G. 読み返し検査の費用（試作の `begin()` に追加、Flash の増分）

| 構成 | remap のみ | GPIO（差分） | 両方 |
|---|---|---|---|
| V003（USART1） | +116 B | +128 B | +244 B |
| X035（USART4） | +68 B | +104 B | +172 B |
| V203（USART1〜3） | +40 B | +96 B | +136 B |

V203 C8T6 で USART3 値 1（PC10 / PC11）を `begin()` に渡すと、検査なしは「成功」と報告して USART3 を確保し、
remap のみ・両方とも失敗を返した。GPIO の比較は、CNF ビットと「MODE が 0 か」だけで行う必要がある
（V006 は MODE の速度ビットが一部しか無く、`3` を書くと `1`、`b` を書くと `9` が読める）。入力の役割には入力設定、
出力の役割には AF 出力設定（I2C は AF オープンドレイン）を使う。

## 結論

- begin 時割り当て（ベクタ共有、設定は const 表、オブジェクトは .bss）は、V003 で現行とほぼ同じ費用、USART の多い系列では
  現行より大幅に軽い。Disable は USART 1本あたり約 100〜120 B を削り、ビルド時固定はさらに数百 B 削る。
- ベクタの別名 + `mcause` の共有ハンドラは V2 / V3A / V4 で動く。
- 「表に無い組み合わせ」は表の照合で必ずエラーにできる。「表にあるがこのチップで使えない」は、remap の読み返しで
  ダイに無い route を、GPIO の読み返しでダイに無いパッドを検出できる。パッケージに出ていないだけのピンは検出できない。
- route 表は (インスタンス, remap 値) → ピン が系列内で一意とは限らない（V203 USART4 値 0）。和集合の表を使う場合、
  remap の読み返しだけでは誤ったピンへの割り当てを防げない。
- V006 系の remap レジスタは 0x0C（ArduinoCore-CH32RV d1a3577 で修正済み）。

## 未解決

- X035 C8T6 の PA9 / PB9 / PB17 で CNF が固定される理由（データシートに記述なし）。ほかの品番での挙動。
- ネストした割り込みでの共有ハンドラ。
- L103 USART3 の OSC_IN / OSC_OUT route のピン。
- AF 番号でピンを選ぶ系列（V205、X305 / X315、H417）の選択の仕組み。
