# E012 銘板: 版情報を build 時に自動で埋める

状態: **完了**(2026-09-04)    <!-- 計画 → 実行中 → 完了 / 中断 -->

規則: [../README.ja.md](../README.ja.md) / 台帳: [../LEDGER.ja.md](../LEDGER.ja.md)

## 問い

**銘板([規則 §5](../README.ja.md))の版情報を、conftest から build 時に自動で埋められるか。埋めると再ビルドのコストが発生するか。**

いまの銘板は `core=esp32:esp32` のような**手書きの固定文字列**と `__DATE__ __TIME__` で、**どの firmware だったかを後から特定できない**。[規則 §5](../README.ja.md) は「その 1 ファイルだけで再現情報が復元できる」ことを求めている。

## 仮説

**埋められる。** `build_config.toml` の `[defines]` は**環境変数名 → C の define 名**の対応なので、conftest が `pytest_configure` で `os.environ` に値を入れれば、その後に走る compile に届くはず。値は文字列として `-DNAME="..."` の形で展開される([E003](../e003_smoke_peer/README.ja.md) でピン番号が文字列になった挙動と同じ)。

**ただし毎回変わる値(実行時刻など)を入れると毎回フルビルドになるおそれがある。** git hash は滅多に変わらないので実害が小さいが、時刻は毎回変わる。

## 反証条件

1. conftest が設定した環境変数が compile に届かない
2. 定義が文字列として展開されず、コンパイルが通らない
3. **毎回変わる値を入れると毎回ビルドし直しになり、実行時間が大きく増える**
4. git 情報が取れない、または dirty 判定ができない

## 方法

1. conftest の `pytest_configure` で環境変数を設定する:
   - `TEST_BANNER_GIT` — `git rev-parse --short HEAD`(未コミットの変更があれば `+dirty` を付ける)
   - `TEST_BANNER_CORE` — `sketch.yaml` の `platform:` 行から抽出(pin されている版)
2. `build_config.toml` でこの 2 つを define に対応付ける。
3. sketch が銘板にそのまま出す。
4. host 側で銘板を正規表現で受け取り、**`git rev-parse --short HEAD` の実値と一致する**ことを確認する。
5. **同じ内容で 2 回連続実行し、2 回目の時間を測る**(ビルドキャッシュが効くか)。
6. **毎回変わる値**(ISO8601 の実行時刻)を追加した場合の時間も測り、5 と比べる(反証条件 3)。

## 対象外

| 落とすもの | 行き先 |
|---|---|
| 実機での確認 | host core で足りる。define の仕組みは profile に依らない |
| 実験 ID の注入 | sketch に書いてあるので不要 |
| `_runs/env.txt` の自動生成 | 銘板が埋まれば `dut.log` だけで足りる。必要になったら別途 |

## 必要な環境

**PC のみ**(常設 v0)。実機不要。

## ベンチ種別

**常設 v0**。

# 結果(2026-09-04)

計画は上のまま変更していない。以下は追記。

## 結果

銘板の実物:

```text
# EXP E012 v1 git=9b16c31+dirty stamp=fixed probe=host target=none build=Sep  4 2026 15:18:33
```

`git rev-parse --short HEAD` の実値 `9b16c31` と一致(未コミットの変更があるので `+dirty` が付く)。

| 条件 | 1 回目 | 2 回目 |
|---|---:|---:|
| 固定値のみ(`stamp=fixed`) | 8.92 s | 9.09 s |
| **毎回変わる値あり**(`stamp=<実行時刻>`) | 8.77 s | 9.08 s |

| 反証条件 | 結果 |
|---|---|
| 1. 環境変数が compile に届かない | 起きず |
| 2. 文字列として展開されない | 起きず |
| 3. 毎回変わる値で実行時間が大きく増える | **起きず**(host core では差が測れない) |
| 4. git 情報が取れない / dirty 判定不可 | 起きず(`+dirty` が付いた) |

## 事実

1. **conftest の `pytest_configure` で設定した環境変数が compile に届く。** `build_config.toml` の `[defines]` が `-DNAME="値"` として展開し、sketch がそのまま文字列として出せる。
2. **git の short hash と dirty 判定が銘板に入る。** `dut.log` 1 つで「どの firmware だったか」が特定できる。**未コミットで走らせたことも記録に残る**(実験中は常に dirty なので、これは正直な表示として有用)。
3. **毎回変わる値を入れても、host core では実行時間の差が測れない**(8.8〜9.1 s の範囲で重なる)。arduino-cli の増分ビルドは、define が変わった 1 ファイルの再コンパイルとリンクだけで済んでいると見られる。

## 候補

- **標準の銘板には git のみを入れ、実行時刻は入れない**(採用)。理由は再ビルドのコストではなく**冗長だから** — 実行時刻は `_runs/<ID>_<UTC>_<profile>/`([E009](../e009_runs_archive/README.ja.md))と `pytest-embedded` のログパスに既に 2 か所ある。
- `core=` も同じ仕組みで `sketch.yaml` から注入できるが、**版は `sketch.yaml` に pin されており、それは commit されている**ので git hash から辿れる。入れなくてよい。

## 未決

- **実機(ESP32)での再ビルドコストは未測定。** host core は sketch が小さいので差が出なかった。ESP32 では sketch の再コンパイルとリンクの分が乗るはずだが、**毎回変わる値を標準の銘板に入れない**と決めたので、当面は影響しない。
- 既存の E001〜E011 の sketch は銘板を手書きのままにしてある(記録済みの銘板を後から変えない)。**この方式は今後の実験に適用する**。

## 反映

- `conftest.py` に `pytest_configure` を追加し、`TEST_BANNER_GIT` を publish。
- [規則 §5](../README.ja.md): 銘板の標準形に `git=` を入れ、注入の仕組みを明記。
- 仕様の status は動かない。
