# E009 退避: 結果の `_runs/` 保存を自動化する

状態: **完了**(2026-09-04)    <!-- 計画 → 実行中 → 完了 / 中断 -->

規則: [../README.ja.md](../README.ja.md) / 台帳: [../LEDGER.ja.md](../LEDGER.ja.md)

## 問い

**実験の生ログを `_runs/<ID>_<UTC>_<profile>/` へ自動で退避できるか。失敗した run でも残るか。**

[規則 §3.4](../README.ja.md) は結果の退避を要求しているが、E001〜E008 は**すべて手動でコピー**していた。手動である限り、忘れた回の結果は失われる。

## 仮説

**できる。** `pytest-embedded` は公開 fixture **`test_case_tempdir`** でテストごとのログディレクトリを提供する。conftest の autouse fixture がこれに依存し、teardown でコピーすればよい。

teardown は**テストの成否に関わらず走る**ので、失敗した run でも残るはず。

## 反証条件

1. `test_case_tempdir` から必要なファイル(`dut.log`、peer のログ)が取れない
2. **失敗した run では退避されない**(teardown が走らない、またはログが未生成)
3. 同じ実験を続けて回すと**前回の退避を上書きする**
4. ID / profile がテストから決まらず、退避先の名前が付けられない

## 方法

**この実験はハーネス自体が対象なので、ハーネスを計測器にできない。** 手順は shell で回し、生成されたファイルを証拠にする。

1. `conftest.py` に autouse fixture を実装する:
   - `test_case_tempdir` に依存し、teardown でその中身を `_runs/<ID>_<UTC>_<profile>/<test 名>/` へコピー
   - **ID は実験ディレクトリ名から導出**(`e001_smoke_host` → `E001`)
   - profile は `--profile` オプション、無ければ `default`
2. **成功する run**: 既存の [E001](../e001_smoke_host/README.ja.md) をそのまま実行し、`_runs/` に出来たものを確認する。
3. **失敗する run**: E009 用に**必ず失敗する**最小の実験(期待値をわざと外す)を用意して実行し、同じく確認する。
4. **連続実行**: 成功する run を 2 回続けて回し、**前回の退避が残っている**ことを確認する(反証条件 3)。

## 対象外

| 落とすもの | 行き先 |
|---|---|
| `_runs/` の中身の書式(env.txt に何を書くか) | 候補 `banner-autofill` と併せて別途 |
| 古い run の掃除・保持期間 | 対象外(**消すのは人の判断**、[規則 §3.4](../README.ja.md)) |
| `build/` の破棄 | 別(conftest の別責務) |
| 波形(`.sr`)の退避 | LA を使う実験が出てから |

## 必要な環境

**PC のみ**(常設 v0)。実機不要。

## ベンチ種別

**常設 v0**。

# 結果(2026-09-04)

計画は上のまま変更していない。以下は追記。

## 結果

| 手順 | 結果 |
|---|---|
| 成功 run(host core) | **退避された** `_runs/E009_20260904T060140Z_default/test_pass_case/dut.log` |
| 2 回目の成功 run | **新しいディレクトリが増え、前回が残った**(`…T060157Z_default`) |
| 失敗 run(`E009_FORCE_FAIL=1`) | **退避された** `_runs/E009_20260904T060210Z_default/test_fail_case/dut.log` |
| peer 実験(E007 を再実行) | **`dut.log` と `peer-device.log` の両方**が退避された |

| 反証条件 | 結果 |
|---|---|
| 1. 必要なファイルが取れない | 起きず(peer ログも含めて取れる) |
| 2. 失敗 run で退避されない | **起きず**(teardown は成否に関わらず走る) |
| 3. 連続実行で上書きする | 起きず(UTC 秒までを名前に含む) |
| 4. ID / profile が決まらない | 起きず(ID は実験ディレクトリ名から導出、profile は `--profile` か `default`) |

## 事実

1. **`test_case_tempdir` に依存する autouse fixture の teardown で、成否に関わらず退避できる。** これが要点で、失敗した run こそログが要るという用途に合う。
2. **peer を使う実験では `peer-device.log` も同じディレクトリに入る。** DUT の数を conftest 側が知らなくてよい(ディレクトリごとコピーするため)。
3. **ID は実験ディレクトリ名から導出できる**(`e001_smoke_host` → `E001`)。[規則 §1.2](../README.ja.md) で ID を path に入れると決めたことが、ここで実利になった。
4. 退避先の名前に UTC 秒を含めるだけで、上書き防止は足りる。

## 候補

- 退避先の `env.txt`(版・機材・要約)も自動生成できるが、**銘板の自動埋め込み**と同じ問題なので候補 `banner-autofill` と併せて扱う。

## 未決

- 古い run の掃除。**消すのは人の判断**([規則 §3.4](../README.ja.md))のままにしてあり、自動削除は入れていない。
- 波形(`.sr`)の退避は LA を使う実験が出てから。

## 反映
