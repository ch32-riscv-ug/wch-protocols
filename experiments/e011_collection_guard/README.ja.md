# E011 ハーネス: 誤爆で実験が走らないことを実プロジェクトで確かめる

状態: **完了**(2026-09-04)    <!-- 計画 → 実行中 → 完了 / 中断 -->

規則: [../README.ja.md](../README.ja.md) / 台帳: [../LEDGER.ja.md](../LEDGER.ja.md)

## 問い

**実験ファイルに `test_` を付けない規約([規則 §1.3](../README.ja.md))は、実験が 10 本を超えた実プロジェクトの構成でも、誤爆から守れているか。**

規約を決めたときの根拠は、空のディレクトリで作った最小の確認だった。**実物で確かめていない。**

## 仮説

**守れている。** `pytest` の既定 `python_files = test_*.py` はディレクトリ走査の条件で、実験ファイルはこれに合致しない。

## 反証条件

1. `pytest`(引数なし)が実験を 1 本でも収集する
2. `pytest <実験ディレクトリ>` が収集する(**ディレクトリ指定でも走ってしまう**)
3. `pytest <実験ファイル>` が収集**されない**(明示指定が効かない)
4. `conftest.py` の autouse fixture([E009](../e009_runs_archive/README.ja.md))が、収集ゼロのときに副作用を起こす

## 方法

`--collect-only` で 4 通りを確認する(実機に触らないので安全):

1. `pytest --collect-only -q`(引数なし)
2. `pytest --collect-only -q e001_smoke_host`(ディレクトリ)
3. `pytest --collect-only -q e001_smoke_host/e001_smoke_host.py`(ファイル)
4. `pytest --collect-only -q .`(カレント全体)

さらに、**回帰テストを置いたら拾われる**ことも確認する(将来 `test_*.py` を追加したときに意図どおり走るか)。一時ファイルで確認し、後で消す。

## 結果

実験 11 本・ディレクトリ 11 個がある状態での `--collect-only`:

| 指定 | 収集件数 |
|---|---:|
| `pytest`(引数なし) | **0** |
| `pytest e001_smoke_host`(ディレクトリ) | **0** |
| `pytest e001_smoke_host/e001_smoke_host.py`(ファイル) | **1** |
| `pytest .`(カレント全体) | **0** |
| 一時的に `_tmp_regression/test_placeholder.py` を置いた状態で引数なし | **1**(その回帰テストだけ) |

| 反証条件 | 結果 |
|---|---|
| 1. 引数なしが実験を収集する | 起きず |
| 2. ディレクトリ指定で収集する | 起きず |
| 3. ファイル指定で収集されない | 起きず(**1 件収集される**) |
| 4. 収集ゼロで conftest が副作用を起こす | 起きず(`_runs/` に何も増えない) |

## 事実

1. **命名規約だけで誤爆から守れている。** 実験が 11 本ある実プロジェクトでも、引数なし・ディレクトリ指定・カレント全体のいずれでも収集ゼロ。
2. **ファイル指定は効く**(1 件)。[E001](../e001_smoke_host/README.ja.md) 事実 5 が実物でも成り立つ。
3. **回帰テスト(`test_*.py`)を置けば、引数なしでそれだけが拾われる。** [規則 §0](../README.ja.md) の「experiment はまとめて走らない / test はまとめて走る」が、追加の仕掛けなしに成立する。
4. marker やオプションによる選別は**要らなかった**。命名だけで足りている。
