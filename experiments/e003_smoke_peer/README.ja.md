## 予備観測(計画前に得てしまったもの)

- **2 台同時 upload は成功**。primary(`s3_peer_host` / ttyACM0)と peer(`s3_peer_device` / ttyACM1)が両方立ち上がり、`?` trigger に**両方とも 1 発で応答**した(`role=primary out=18 in=19` / `role=peer out=19 in=18`)。
- **primary が GPIO18 を HIGH に駆動しても、peer の GPIO18 は 0 のまま**(入力は pull-down)。
- → **「18↔18 / 19↔19 で直結」という仮定が誤っている**か、その 2 本以外に繋がっている。

## 問い

**peer 2 台を実験に使えるか。** 具体的には次の 3 つ:

1. 2 台を同時に build / upload / monitor できるか
2. device lock が 2 枚それぞれに効くか
3. **2 台の間に実際に繋がっている線はどれとどれか**(片方の GPIO 遷移をもう片方が観測できるか)

## 仮説

1 と 2 は**成立する**(予備観測で 1 は確認済み)。3 については **2 本の線が繋がっているが、対応関係は未知**。ESP32-S3 の native USB は **GPIO19(D−)/ GPIO20(D+)** なので、USB 用の配線であれば **19↔19 / 20↔20** の可能性がある。

## 反証条件

1. 2 台目(peer)が build / upload / connect のいずれかで失敗する
2. **候補ピンのどの組合せでも遷移が観測されない**(= 直結が存在しない、または駆動できないピン)
3. 観測はできるが**片方向のみ**(双方向に使えない)

## 方法

**仮定を置かずに走査して topology を発見する。**

1. 両 board に同じ sketch を焼く。host からの行コマンドで任意の候補ピンを操作できるようにする:
   - `D<n>` = ピン n を OUTPUT にして HIGH
   - `L<n>` = ピン n を OUTPUT にして LOW
   - `R<n>` = ピン n を INPUT_PULLDOWN にして読む → `READ <n>=<0|1>`
   - `Z` = 候補ピンをすべて INPUT_PULLDOWN に戻す(解放)
2. 候補ピンは **17 / 18 / 19 / 20 / 21**(`.env` の `TEST_PEER_PINS`)。strapping ピンと flash ピンは含めない。
3. **行列を取る**: primary が候補ピン p を HIGH → peer が候補ピン q をすべて読む → p を LOW に戻す。これを全 p について繰り返す。
4. **逆向きも同じく取る**(peer が駆動、primary が読む)。
5. 入力は **pull-down** にするので、未接続なら常に 0。`READ=1` は**接続の実証**になる。

## 結果

| 反証条件 | 結果 |
|---|---|
| 1. peer が build / upload / connect で失敗 | 起きず |
| 2. どの組合せでも遷移が観測されない | 起きず |

**接続行列**(行 = 駆動、列 = 読出。1 = 観測された)

```text
primary -> peer            peer -> primary
      17  18  19  20  21         17  18  19  20  21
 17    0   0   0   0   0    17    0   0   0   0   0
 18    0   0   0   0   0    18    0   0   0   0   0
 19    0   0   1   0   0    19    0   0   1   0   0
 20    0   0   0   1   0    20    0   0   0   1   0
 21    0   0   0   0   0    21    0   0   0   0   0
```

応答までの trigger 回数: primary 1 回 / peer 1 回。

## 事実

1. **2 台の同時 build / upload / monitor が成立する。** `peers["device"]` で peer を操作でき、両 board とも trigger に 1 発で応答した。
2. **繋がっているのは GPIO19↔19 と GPIO20↔20 の 2 本**(双方向)。**予備観測で仮定した 18↔18 / 19↔19 は誤り**で、17・18・21 はどこにも繋がっていない。
3. これは **ESP32-S3 の native USB ピン(D−=GPIO19 / D+=GPIO20)**。USB host/device 試験用の配線という説明と一致する。仮説で挙げた「19↔19 / 20↔20 の可能性」が当たった。
4. **入力を pull-down にしたことで、未接続が常に 0 になり `READ=1` が接続の実証になった。** 走査で topology を発見する形にしたのが正解で、仮定を検算する形のままでは「繋がっていない」ことしか分からなかった。

## 候補

- **peer 対は「2 線の直結」として使える**。RVSWD は SWCLK + SWDIO の 2 線なので**形が一致する**。
- ただし 19/20 は native USB ピンなので、**その 2 本を線として使う間は native USB を使えない**。現在は CH340 経由の UART を使っているので支障はない。

## 未決

- device lock が 2 プロセス間で実際に排他するか → 候補 `device-lock`(この実験では 2 枚に別々の lock が取れることまで)。
- この 2 線で RVSWD の速度・波形が成立するか → 別実験。ここでは**繋がっているかどうか**だけを見た。
