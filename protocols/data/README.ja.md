## `wchlink-commands.csv` の列

1 行 = 1 コマンド × 1 範囲(probe の variant と fw、chip)。同じコマンドを別の範囲で測ったら、同じ `id` で行を分ける。

| 列 | 意味 |
|---|---|
| `id` | 安定した ASCII の識別子。pc-to-link.ja.md のアンカー(`#cmd-rst-out` の形)と同じ。変えない |
| `section` | pc-to-link.ja.md の節(`4`、`5`、`5b`、`7`、`8`、`10b`) |
| `name` | 人向けの名前 |
| `request_frame` | host → probe の **frame 全体**(`81 cmd len payload…`)。hex を空白で区切る。`{name}` / `{name:be32}` は可変の field(`be32` = big endian 4 byte、型の無いものは 1 byte)。空 = byte 列が分かっていない |
| `cmd` | frame の 2 byte 目 |
| `sub` | payload の先頭 byte が sub-command として働く場合のその値。無ければ空 |
| `payload` | `len` の後ろの byte のうち、`sub` 以外の可変部分の型(例 `addr:u8 data:be32 op:u8`)。固定の byte は hex |
| `response` | probe → host の応答(`82 cmd len payload…`)。`(…)` は frame でない応答(生の byte、応答なし、再列挙)。`…` は内容を記録していない部分 |
| `status` | [README の status 語彙](../../README.md#status) の 1 語。`accepted` / `effect` / `evidence` から決める |
| `evidence` | 根拠の種類。`;` 区切り: `usb-capture` / `wire-capture` / `hw-log` / `adc` / `impl-agree` / `source` / `binary` |
| `scope_probe` | 範囲の probe: `linke` / `ch549` / `linkw` / `any`。空 = 実機で測っていない |
| `scope_fw` | 範囲の probe firmware(`2.22` の形)。空 = 実機で測っていない |
| `scope_chip` | 範囲の target(空白区切り)。`-` = target に関係しない、または target なしで測った |
| `accepted` | probe が受理したか(成功の応答を返したか): `yes` / `no` / `unknown` / `n/a` |
| `effect` | 主張どおりの効果が target / 線に出たか: `yes` / `no` / `unknown` / `n/a` |
| `aliases` | 他の実装での名前。`impl=name` を `;` で区切る(`wlink=` / `openocd=` / `minichlink=` / `probe-rs=`)。wlink と probe-rs は型・関数の名前、WCH OpenOCD と minichlink は名前の付いた型が無いのでその frame を送る関数の名前。byte 列が違うものは括弧で frame を添える。`-` = 下の 4 実装のどれにも無い。同じ `id` で同じ `request_frame` の 2 行目以降は空(1 行目を見る) |
| `source` | 出典(先行実装の file と行、実験の E 番号、capture)。`;` 区切り |
| `note` | 説明(日本語) |
